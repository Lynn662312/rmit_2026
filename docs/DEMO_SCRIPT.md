# SafeSpeak: 2-Minute Demo Video Script

> Use synthetic data only. This video demonstrates the current UI prototype with simulated records, roles, and decryption results. It does not claim that real TideCloak security is integrated.

| Time | Website action | English narration |
|---|---|---|
| 0:00–0:20 | Show the SafeSpeak page and wisteria design. | “SafeSpeak is a campus reporting prototype for students facing bullying or harassment. Its calm, focused interface gives students a space to speak up and share what they feel ready to share.” |
| 0:20–0:45 | On the student page, enter a fictional report and select **Encrypt & submit**. | “Students begin with one simple form. There are no unnecessary identity fields or attachments. After submission, a confirmation displays the report reference and submission time.” |
| 0:45–1:05 | Select **View my reports**, then open the report that was just submitted. | “Students can return to previous submissions through My reports. They can select a record to retrieve its reference, date and encrypted-content view. Reading the original text requires separate decryption permission.” |
| 1:05–1:30 | Use the Role menu to switch to Investigator, select the report, select **Decrypt report**, and then hide the content. | “The investigator workspace brings reports into a focused review panel. Content is revealed through an explicit action and can be hidden again. This preview demonstrates the interaction using simulated records and decryption results.” |
| 1:30–1:45 | Switch to School Admin and show the disabled decryption button. | “The administrator preview shows a restricted interface, where decryption is unavailable. These workspace states illustrate the intended experience; the role menu itself does not enforce security.” |
| 1:45–2:00 | Return to the student page. | “SafeSpeak combines a supportive reporting experience with submission history and a clear review workflow. This demonstration uses synthetic data. Real TideCloak authentication, permissions and encryption still require integration and verification.” |

## Recording checklist

- Keep the UI preview or simulated-data disclaimer visible.
- Use a short fictional report with no real names or incidents.
- Do not show tokens, environment variables, personal accounts, or secrets.
- Do not describe the role menu or mock decryption as security enforcement.
- Record the screen first and add narration afterward if that is faster.
- Add automatic subtitles and trim loading or navigation delays.
- Keep the final video under two minutes and under 100 MB.
- Replace `VIDEO_ID_HERE` in the repository README after uploading the video to YouTube.
